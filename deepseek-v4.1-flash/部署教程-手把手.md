# DeepSeek-V4.1-Flash 双机 DGX Spark 部署(手把手教程)

> 本目录对应方案:[tonyd2wild/DeepSeek-V4.1-Flash-TP2-and-TP4-DGX-Sparks](https://github.com/tonyd2wild/DeepSeek-V4.1-Flash-TP2-and-TP4-DGX-Sparks) 的 **TensorFold TP2 lane**(两台 Spark)
>
> 底层引擎与 recipe:[bertholomus/TensorFold](https://github.com/bertholomus/TensorFold) 分支 `deepseek-v41-zig` @ `3ff3b2a` + 三个补丁;recipe [deepseek-v4.1-tensorfold-tp2-2xgb10](https://github.com/bertholomus/deepseek-v4.1-tensorfold-tp2-2xgb10) v0.6.1
>
> 本目录跑通的是 **Mia-AiLab EXL3 2.9bpw(EAQ v1)** 权重,不是文档默认的 LibertAI 版(见 [`部署流程.md`](./部署流程.md) 第 1 节的说明)。

---

## 0. 你需要准备的东西

| 项目 | 要求 |
|---|---|
| 两台 DGX Spark | 每台 128 GB 统一内存,启动时每台需 ~108 GiB 可用(权重 99 GiB + KV pool) |
| 两条 QSFP 直连线 | 两台 CX7 对连(rail 1 + rail 2),本集群是 `192.168.100.0/24` 和 `192.168.101.0/24` |
| 磁盘 | head 上约 390 GB(权重),worker 约 490 GB(权重 + rank cache) |
| Docker 镜像 | `nvcr.io/nvidia/pytorch:26.07-py3`(24.3 GB) |
| SSH | head 能免密 ssh 到 worker 和 **自己**(serve 脚本用 ssh 到本机执行容器) |

**两台机器角色**:
- **head(rank 0)** `spark-adeb` `192.168.101.1`:跑 `./start_tp2.sh`,对外服务在 `:8000`
- **worker(rank 1)** `spark-d705` `192.168.101.2`:由 head 通过 ssh 拉起,不需要手动登录

## 1. 前置检查【两台】

### 1.1 网络与 RDMA

```bash
hostname; ip -br addr | grep -E '192\.168\.10[01]'
ibv_devices          # 应该看到 rocep1s0f0、roceP2p1s0f0
ssh sakana@192.168.101.1 hostname   # 关键:head 必须能 ssh 自己
ssh sakana@192.168.101.2 hostname   # head 能到 worker
```

### 1.2 内存与磁盘

```bash
awk '/MemAvailable/ {printf "%.1f GiB 可用\n", $2/1048576}' /proc/meminfo   # 需要 ≥ 108
df -h /home | tail -1                                                       # head 剩 ≥ 400 GB
docker ps                                                                   # 不应有占显存的容器
```

### 1.3 镜像

head 与 worker 都要有:

```bash
docker image inspect nvcr.io/nvidia/pytorch:26.07-py3 >/dev/null && echo OK
```

> 本集群实际情况:worker 能直连 nvcr.io 拉取;head 的 docker daemon 配了个已失效的代理(`127.0.0.1:7890`),
> 拉取报 `Get "https://nvcr.io/v2/": EOF`。解决办法是从 worker 灌过来:
>
> ```bash
> # 在 head 上执行
> ssh dgx2 'docker save nvcr.io/nvidia/pytorch:26.07-py3' | docker load
> ```
>
> 大约 12 分钟(2 台 24 GB)。灌完 `docker images` 里能看到同一个 image id。

## 2. 拿代码与权重【head】

### 2.1 引擎与 recipe

```bash
mkdir -p ~/dgx-deepseek-tp2 && cd ~/dgx-deepseek-tp2

# Zig 0.17.0(编译用,不需要系统装 zig)
curl -sSL -o zig.tar.xz https://ziglang.org/download/0.17.0/zig-aarch64-linux-0.17.0.tar.xz
tar xf zig.tar.xz && rm zig.tar.xz

# 引擎:分支 deepseek-v41-zig 固定在 3ff3b2a,再打三个补丁
git clone -b deepseek-v41-zig https://github.com/bertholomus/TensorFold.git engine
cd engine
git checkout -q 3ff3b2a
git checkout -q -b tp2-lane
git cherry-pick 5940208          # 无 GPU 也能写 rank cache 的那个提交
# 冲突解决:README.md 与 tools/dsv41-zig/kit/{make_rope,make_bias_vl}.py、verify_kit.sh
#           一律保留分支(HEAD)一侧,丢弃 5940208 带来的旧版
git add README.md tools/dsv41-zig/kit/ && git cherry-pick --continue
# 另外两个补丁来自方案仓库
git am <方案仓库>/runs/2026-10-18-1017-tensorfold-tp2/patches/0002-*.patch \
       <方案仓库>/runs/2026-10-18-1017-tensorfold-tp2/patches/0003-*.patch
cd ..
git clone https://github.com/bertholomus/deepseek-v4.1-tensorfold-tp2-2xgb10.git recipe
git -C recipe checkout -q v0.6.1

# make_rope.py 需要 PyTorch 版 TensorFold 的 deepseek_v41.families
git clone --depth 1 -b deepseek-v41-tp2 https://github.com/bertholomus/TensorFold.git tfpy
```

### 2.2 权重(本目录用 Mia-AiLab EXL3 2.9bpw)

```bash
# 主权重(39 个分片,196 GiB)
HF_ENDPOINT=https://hf-mirror.com hf download \
  Mia-AiLab/DeepSeek-V4.1-Flash-1017-EXL3-EAQ-v1-2.9-bpw \
  --local-dir ~/models/DeepSeek-V4.1-Flash-1017-EXL3-EAQ-v1-2.9-bpw

# Engram 表 = base checkpoint 的 shard 47/48(2 × 101.5 GB),放 <模型>/base-engram/
for s in 47 48; do
  aria2c -c -x8 -s8 -k 64M --auto-file-renaming=false \
    "https://hf-mirror.com/deepseek-ai/DeepSeek-V4.1-Flash-1017/resolve/1bae0e1088993b9b82de08f59de5be5a34e42170/model-000${s}-of-00048.safetensors" \
    -d ~/models/DeepSeek-V4.1-Flash-1017-EXL3-EAQ-v1-2.9-bpw/base-engram
done
```

> 两个 100 GB 级文件用 `hf` + Xet 在本环境频繁失败(`CAS Client Error` / `401`),用 aria2c 多连接稳定。

### 2.3 组运行时模型目录

引擎只读这个目录,不是原始权重目录:

```bash
D=~/models/DeepSeek-V4.1-Flash-1017-EXL3-EAQ-v1-2.9-bpw
B=~/dgx-deepseek-tp2
mkdir -p $B/{model,engram,kit,cache/rank-cache,logs,engine-bin}
for f in config.json quantization_config.json model.safetensors.index.json tokenizer.json tokenizer_config.json; do
  cp $D/$f $B/model/
done
cp -r $D/encoding $B/model/
cp <方案仓库>/runs/2026-10-17-1017-tensorfold/launch/chat_template.jinja $B/model/
# 39 个分片 + Engram 表用符号链接,省 390 GB
for i in $(seq -w 1 39); do ln -sfn $D/model-000$i-of-00039.safetensors $B/model/model-000$i-of-00039.safetensors; done
for s in 47 48; do ln -sfn $D/base-engram/model-000${s}-of-00048.safetensors $B/engram/model-000${s}-of-00048.safetensors; done
```

## 3. 编译引擎【head,不需要 GPU】

```bash
cd ~/dgx-deepseek-tp2
# 写 build.sh(内容见 scripts/setup.sh 里的 do_build),然后:
docker run --rm --name tf1017-build --network host --user "$(id -u):$(id -g)" \
  -v ~/dgx-deepseek-tp2:/work nvcr.io/nvidia/pytorch:26.07-py3 bash /work/build.sh
mkdir -p engine-bin && cp -f engine/zig-out/bin/* engine-bin/
```

编译约 3 分钟。产出 13 个二进制,其中三个关键:
`tensorfold`(rank 0 服务)、`tf-dsv41-lanes`(rank 1)、`tf-dsv41-rank-cache`(纯 CPU 生成权重切片)。

## 4. 生成内核包 kit【head】

kit 里 4 个 RoPE 表(136 MB × 4)和 vision bias 不在 git 里,要本地生成:

```bash
cp -r recipe/kit/* ~/dgx-deepseek-tp2/kit/        # 先铺 AOT cubins、MANIFEST 等

# RoPE 表:在容器里用 PyTorch 版 TensorFold 算,跑完自动比对 rope.json 的 sha256
docker run --rm --network none --user "$(id -u):$(id -g)" -e HOME=/tmp \
  -v ~/dgx-deepseek-tp2/model:/model:ro -v ~/dgx-deepseek-tp2/kit:/kit \
  -v ~/dgx-deepseek-tp2/tfpy/src:/tfpy:ro --entrypoint bash nvcr.io/nvidia/pytorch:26.07-py3 \
  -c 'export PYTHONPATH=/tfpy; python3 /kit/tools/make_rope.py /model /kit'
# 期望: 4 个文件各 142606336 字节, sha256 ok

# vision bias:从 EXL3 包里 43 个 *.ffn.gate.bias_vl 张量字节级拷出
cd ~/dgx-deepseek-tp2/model && python3 ../kit/tools/make_bias_vl.py . ../kit/vision/gate_bias_vl.safetensors

# 自检
bash ~/dgx-deepseek-tp2/kit/tools/verify_kit.sh
```

**预期的自检结果:221 个文件里 220 匹配,1 个 DIFFERS(`vision/gate_bias_vl.safetensors`)。**
这不是错误,原因见 [`部署流程.md`](./部署流程.md) 第 5 节:我们的包比 LibertAI 包多带了 MTP 层的
3 个 `[128]` 形状 bias,而引擎按张量逐个读、只要求形状是 `[384]` 的层层 bias,不影响加载。

## 5. 生成 rank cache 与 token map【head,纯 CPU】

TP2 每台机器只加载自己那一半权重,需要先切片:

```bash
cd ~/dgx-deepseek-tp2
export PATH=$PWD/engine-bin:$PATH
for r in 0 1; do
  out=$PWD/cache; [ $r = 1 ] && out=$PWD/cache-r1
  mkdir -p $out/rank-cache
  nice -n 19 tf-dsv41-rank-cache $PWD/model $out/rank-cache $r 2
done
# 期望: 每个 rank 打印 {"data_bytes": 106107109192, "entries": 143770, ...}

# Engram 压缩 token map
docker run --rm --network none --user "$(id -u):$(id -g)" -e HOME=/tmp \
  -v $PWD/model:/model:ro -v $PWD/cache:/cache -v $PWD/engine/tools/dsv41-zig/inputs:/tools:ro \
  --entrypoint python3 nvcr.io/nvidia/pytorch:26.07-py3 /tools/make_token_map.py /model /cache/dsv41_token_map.json
# 期望: 129280 token ids -> 99092 compressed ids
```

每个 rank cache 约 106 GB,单次约 2 分钟(磁盘 IO 为主)。

## 6. 同步到 worker【head】

```bash
B=~/dgx-deepseek-tp2
W=sakana@192.168.101.2
ssh $W "mkdir -p $B/{model,engram,kit,cache/rank-cache,logs,engine-bin}"
rsync -a --delete $B/engine-bin/ $W:$B/engine-bin/
rsync -a --delete $B/kit/        $W:$B/kit/
rsync -aL $B/model/              $W:$B/model/     # -L:把符号链接解成实体文件
rsync -aL $B/engram/             $W:$B/engram/
rsync -a  $B/cache-r1/rank-cache/ $W:$B/cache/rank-cache/
rsync -a  $B/cache/dsv41_token_map.json $W:$B/cache/
```

> `-L` 不能省:不加的话 rsync 只搬符号链接本身,worker 上就是一堆断链。
> 总计约 490 GB。本集群实测两条 CX7 同时跑、约 20 MB/s 单向,合起来约 4–5 小时。

## 7. 配置并启动【head】

```bash
cd <本仓库>/deepseek-v4.1-flash
cp config/tp2.env.example scripts/local.env
vi scripts/local.env            # 至少改 NODES / MASTER_IP / NET_IF / RDMA_HCA

./scripts/precheck_tp2.sh       # 全部 PASS 才继续
./scripts/start_tp2.sh
```

启动过程:rank 1(`tf-dsv41-lanes`)先在 worker 起来,然后 rank 0(`tensorfold serve`)在 head 起来。
加载权重约 30 秒(实测 27.1 s),之后脚本每 5 秒轮询 `/v1/models`,起来后自动做一次 chat 检查,
成功会打印 `up and answering on 192.168.101.1:8000`。

日志:
```bash
tail -f ~/dgx-deepseek-tp2/logs/tp2-lane.log              # head (rank 0)
ssh dgx2 'tail -f ~/dgx-deepseek-tp2/logs/tp2-lane.log'   # worker (rank 1)
```

## 10. 常见问题

**Q: precheck 报 `MemAvailable < 108`**
先停掉其他占显存的容器(`docker ps` / `nvidia-smi`)。本 lane 每节点要 99 GiB 权重,加 KV pool 后余量只有 6–8 GiB。

**Q: 卡在 `rank 0 did not come up`**
看 `logs/tp2-lane.log`。最常见是 rank 1 没起来就等 rank 0,两个 rank 的 `--streams` / `--pool` 必须对上:
rank 1 的 `--pool` 等于 rank 0 的 `--context`,rank 1 的 `--streams` 等于 rank 0 的 `TF_DS_STREAMS`。

**Q: 报 `NoVisionKit`**
kit 里缺 `vision/torch_fmha_sm120.cubin` 或 `vision/gate_bias_vl.safetensors`,回第 4 步重做。

**Q: 报 `NoEngramTables`**
`ENGRAM_DIR` 里没放 shard 47/48,或者放的是软链但容器挂载后断链(容器里挂载的是实体目录,软链目标必须在挂载内)。

**Q: hf 下载 100 GB 文件总失败**
换 aria2c(见 2.2)。
