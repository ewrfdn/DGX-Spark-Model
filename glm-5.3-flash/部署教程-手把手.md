# GLM-5.3-Flash 双 DGX Spark 部署(手把手教程)

> 本目录对应方案:[MiaAI-Lab/GLM-5.3-Flash-EXL3-2x-DGX-Sparks-TensorFold](https://github.com/MiaAI-Lab/GLM-5.3-EXL3-2x-DGX-Sparks-TensorFold)
>
> 面向零基础用户,每一步都有完整命令,从零跟到尾即可部署成功。
> 详细原理和进阶参数见同目录 [`部署流程.md`](./部署流程.md)。

---

## 0. 你需要准备的东西

| 项目 | 要求 |
|---|---|
| 两台 DGX Spark | 每台 128 GB 统一内存,启动时每台需 ~110 GiB 空闲 GPU 内存 |
| 一根 QSFP 线 | 直连两台的 CX7 网口 |
| 磁盘空间 | 每台 ~205 GB(checkpoint ~176 GB + DFlash2 ~2.3 GB + Docker 镜像 ~25 GB) |
| 网络 | 两台都能访问 HuggingFace(下模型)和 ghcr.io(拉镜像),能互 ping |
| HuggingFace 账号 | 不需要,checkpoint 是公开的 |

**两台机器的角色**:
- **head(主机)**:运行 `./start.sh` 和 API 服务,模型从这里下载
- **worker(从机)**:通过 SSH 由 head 自动操作,不需要克隆仓库

> 下文命令中,标注【head】的只在第一台上执行,标注【worker】的只在第二台上执行,标注【两台】的两台都要执行。

## 1. 前置检查【两台】

### 1.1 确认用户名和 IP

```bash
whoami          # 记下用户名,后面要用
hostname -I     # 记下这台机器的 IP
```

### 1.2 确认 GPU 正常

```bash
nvidia-smi
```

能看到 GPU 信息即可。**注意空闲内存**:部署前每台至少 ~110 GiB 空闲,如果有其他任务在跑,先停掉:

```bash
docker ps                       # 看有没有其他容器占着 GPU
docker stop <容器名>            # 有的话停掉
```

### 1.3 确认磁盘空间

```bash
df -h /    # Avail 一列至少 210 GB
```

---

## 2. 连接两台的 CX7 直连链路【两台】

这一步让两台机器之间有一条高速直连通道(用 QSFP 线),它们靠这个交换推理数据。

### 2.1 插线

QSFP 线两端分别插进两台 Spark 的 CX7 网口(机器后面带 QSFP 的口)。

### 2.2 查看网口名字【两台】

```bash
ip link
```

找到名字类似 `enp1s0f0np0`、`enP2p1s0f0np0` 的网卡(不是 `eth0`、`lo`、`docker0` 那些常规的),这就是 CX7 的口。**一个 QSFP 口会在系统里出现两个网口**(硬件设计如此,相当于两条并行通道),都要配。

### 2.3 配置 IP【两台】

在 **head** 上执行(假设网口是 `enp1s0f0np0` 和 `enP2p1s0f0np0`):

```bash
sudo ip addr add 192.0.2.1/24 dev enp1s0f0np0
sudo ip addr add 192.0.2.3/24 dev enP2p1s0f0np0
sudo ip link set enp1s0f0np0 up
sudo ip link set enP2p1s0f0np0 up
```

在 **worker** 上执行(同两个网口名):

```bash
sudo ip addr add 192.0.2.2/24 dev enp1s0f0np0
sudo ip addr add 192.0.2.4/24 dev enP2p1s0f0np0
sudo ip link set enp1s0f0np0 up
sudo ip link set enP2p1s0f0np0 up
```

### 2.4 验证连通【head】

```bash
ping -c 3 192.0.2.2
```

能通就说明链路 OK。不通的话检查:线插对了没、两步的网口名是不是一致、防火墙(`sudo ufw status`)。

---

## 2.5 (推荐)把 IP 配置改成持久的

上面 2.3 的配置**重启后会丢**。如果想持久化,装 `netplan` 配置或用 NetworkManager,参考:

```bash
# 方法:写一个 systemd 服务开机自动配
sudo tee /etc/systemd/system/cx7-link.service <<'EOF'
[Unit]
Description=CX7 direct link IP config
After=network.target

[Service]
Type=oneshot
ExecStart=/bin/bash -c 'ip addr add 192.0.2.1/24 dev enp1s0f0np0 2>/dev/null; ip addr add 192.0.2.3/24 dev enP2p1s0f0np0 2>/dev/null; ip link set enp1s0f0np0 up; ip link set enP2p1s0f0np0 up'
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now cx7-link.service
```

> 记得把上面的 IP 换成 worker 的(`192.0.2.2` / `192.0.2.4`),并放在 worker 上执行。

## 3. 安装基础软件【两台】

### 3.1 安装 Docker(如果已有可跳过)

```bash
# 官方脚本安装
curl -fsSL https://get.docker.com | sudo sh

# 把自己的用户加进 docker 组(免 sudo 用 docker)
sudo usermod -aG docker $USER

# 重登或执行这句让组生效
newgrp docker

# 验证(不需要 sudo)
docker --version
docker info | grep -i runtime    # 应该能看到 nvidia 字样
```

> DGX Spark 的系统镜像通常自带 NVIDIA runtime。如果 `docker info` 里没有 nvidia,安装:
> `sudo apt-get install -y nvidia-container-toolkit && sudo systemctl restart docker`

### 3.2 安装 rsync(文件同步工具,head 复制模型到 worker 要用)

```bash
sudo apt-get update && sudo apt-get install -y rsync openssh-server
```

### 3.3 确认 worker 能被 SSH 登录【worker】

```bash
sudo systemctl enable --now ssh
```

---

## 4. 配置 head 到 worker 的 SSH 免密【head】

`start.sh` 会从 head 通过 SSH 操控 worker(启容器、传模型),所以要配好免密登录。

```bash
# 4.1 如果还没有 SSH 密钥,生成一个(一路回车即可)
ssh-keygen -t ed25519

# 4.2 把公钥传给 worker(会要一次密码,之后就不需要了)
ssh-copy-id <worker的用户名>@<worker的IP>

# 4.3 验证免密成功:下面这条不输密码、不报错、没有任何输出,就成功了
ssh -o BatchMode=yes <worker的用户名>@<worker的IP> true && echo SSH-OK
```

看到 `SSH-OK` 就代表这一步完成。

docker tag ghcr.io/miaai-lab/glm-5.3-flash-exl3-2x-dgx-sparks-tensorfold@sha256:cbb4b3c66273e2965dd40a7227e7a5243db333fe250113fb3987462ad4f12588 tensorfold-glm53:v0.6.0

## 5. 克隆方案仓库并配置【head】

```bash
# 5.1 克隆(如果网络不稳,多重试几次)
git clone https://github.com/MiaAI-Lab/GLM-5.3-Flash-EXL3-2x-DGX-Sparks-TensorFold.git
cd GLM-5.3-Flash-EXL3-2x-DGX-Sparks-TensorFold

# 5.2 从本 repo 拿配置模板(本 repo 已克隆在 ~/workspace/DGX-Spark-Model)
cp ~/workspace/DGX-Spark-Model/glm-5.3-flash/config/local.sh.example scripts/local.sh

# 5.3 编辑,把 WORKER 改成你的实际值
nano scripts/local.sh
```

打开后只需要改一行(`Ctrl+O` 保存,`Ctrl+X` 退出):

```bash
WORKER=<worker的用户名>@<worker的IP>     # 例如 WORKER=sakana@192.0.2.2
```

**就这一行。** 其他都不用动。

---

## 6. 启动!【head】

```bash
./start.sh
```

### 首次运行会发生什么(全自动)

1. 预检两台机器(Docker、GPU、SSH、链路、磁盘)
2. 拉取/确认 Docker 镜像(两台)
3. **下载模型**(~176 GB checkpoint + ~2.3 GB DFlash2,存到 `~/.cache/huggingface`)—— 如果你的模型已经由后台任务下好,脚本会直接用,不重复下载
4. 把模型从 head 复制到 worker(rsync,走 CX7 链路,~166 GiB,要一阵子)
5. 编译 CUDA 内核(每镜像一次)
6. 启动两个 rank + API 服务
7. 自动跑冒烟测试

最后看到:

```
GLM-5.3-Flash-EXL3 is now LIVE! on port 8888
```

就部署成功了!之后每次启动/重启只要 2-6 分钟(只加载权重)。

### 如果中途停了

脚本会打印明确的报错和怎么办,常见三种:

| 报错 | 原因 | 解决 |
|---|---|---|
| `only N GiB memory available` | 机器上有别的 GPU 任务 | `docker ps` 找到并停掉,再跑 `./start.sh` |
| `no RoCE device or RoCE v2 GID for the link` | CX7 链路没配好 | 回到第 2 步检查 IP 和 ping |
| 磁盘空间不足 | 空间不够 | 清理磁盘(`docker system prune` 清理无用镜像) |

## 7. 验证与使用【任意能访问 head 的机器】

### 7.1 快速验证

```bash
curl -s http://<head的IP>:8888/health      # 服务健康状态
curl -s http://<head的IP>:8888/v1/models   # 模型列表

# 发第一条测试请求
curl -s http://<head的IP>:8888/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "GLM-5.3-Flash-EXL3",
    "messages": [{"role": "user", "content": "写一个 Python 斐波那契函数"}],
    "max_tokens": 2000
  }'
```

### 7.2 Python 客户端(OpenAI SDK)

```python
from openai import OpenAI

client = OpenAI(base_url="http://<head的IP>:8888/v1", api_key="none")

resp = client.chat.completions.create(
    model="GLM-5.3-Flash-EXL3",
    messages=[{"role": "user", "content": "你好,介绍一下你自己"}],
    max_tokens=4096,
)
print(resp.choices[0].message.reasoning_content)  # 思考过程(可打印可不打印)
print(resp.choices[0].message.content)            # 正式回答
```

> 模型默认先思考再回答,`max_tokens` 记得给够(默认上限 32768)。

## 8. 日常运维

```bash
./start.sh restart      # 改完配置后重启(不断已有连接的话直接重跑)
./stop.sh               # 停止服务,释放两台的 GPU 内存
docker logs -f glm53-flash-tf                 # 看 head(rank 0)日志
ssh <worker用户>@<worker IP> docker logs -f glm53-flash-tf   # 看 worker(rank 1)日志
```

历史日志自动存在 `~/.cache/tensorfold-glm53/logs/` 下(gzipped,`zless` 查看),排障时把两台的最新日志都带上。

## 9. 最简流程回顾(懂了之后看这个)

```
①【两台】插 QSFP 线 → 配 CX7 口 IP(192.0.2.1/2)→ ping 通
②【两台】装 Docker + rsync,用户入 docker 组
③【head】ssh-copy-id 到 worker
④【head】克隆方案仓库 → cp 本repo的 config/local.sh.example scripts/local.sh
        → 改 WORKER=<user>@<worker IP>
⑤【head】./start.sh(首次全自动:镜像→模型→复制→启动)
⑥ curl http://<head>:8888/v1/chat/completions 验证
```
