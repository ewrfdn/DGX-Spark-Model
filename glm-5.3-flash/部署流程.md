# GLM-5.3-Flash 双 DGX Spark 部署流程

> 基于 [MiaAI-Lab/GLM-5.3-Flash-EXL3-2x-DGX-Sparks-TensorFold](https://github.com/MiaAI-Lab/GLM-5.3-Flash-EXL3-2x-DGX-Sparks-TensorFold) 方案整理。
>
> 目标:在 **2 台 NVIDIA DGX Spark**(GB10,各 128 GB 统一内存,CX7 直连)上通过 **TensorFold v0.6.0 + 77 个补丁** 部署 GLM-5.3-Flash,提供 OpenAI 兼容 API(端口 8888),支持 **4 路并发**、**1,048,576 token 完整上下文**、**图像/视频输入**、工具调用与结构化输出。

---

## 1. 需要下载的模型与文件

| 文件 | 位置 | 大小 | 说明 |
|---|---|---|---|
| **主模型 checkpoint** `Mia-AiLab/GLM-5.3-Flash-EXL3-4bpw-TensorFold` | Hugging Face | **~176 GB** | Mia AI Lab 自制 EXL3 量化(路由专家 4bit,BF16 其余),针对 TensorFold 推理校准,Apache 2.0 |
| **DFlash2 投射器** `incoai/GLM-5.3-Flash-DFlash2` | Hugging Face | **~2.3 GB** | 投射解码加速,+5-10% decode 速度。**CC BY-NC-ND 4.0,仅限非商用**;商用可改用 checkpoint 自带 MTP 头(`DRAFTER=mtp`,仅单并发) |
| Docker 镜像 `ghcr.io/miaai-lab/glm-5.3-flash-exl3-2x-dgx-sparks-tensorfold:v0.6.0-<hash>` | GHCR | **~25 GB/台** | TensorFold v0.6.0 + 全部补丁 + PyAV + xgrammar,基于 `nvcr.io/nvidia/pytorch:26.07-py3` |
| (可选)Ablit 权重 `Mia-AiLab/GLM-5.3-Flash-EXL3-4bpw-TensorFold-Ablit` | Hugging Face(gated,需登录同意条款 + HF_TOKEN) | ~176 GB | 消融版,默认关闭思考 |

**下载方式**:以上模型/镜像**均由 `scripts/prepare.sh` 在首次 `./start.sh` 时自动下载**,缓存到 `~/.cache/huggingface`(checkpoint 和 DFlash2 固定在测量过的 revision 上)。

- 每台 Spark 磁盘需求:**~205 GB**(checkpoint ~176 GB + DFlash2 ~2.3 GB + 镜像 ~25 GB)
- 可选:在 head 上安装 `hf` CLI(下载更快)并配置 `~/.cache/huggingface/token` 或 `HF_TOKEN`
- Worker 默认通过 rsync 从 head 复制权重(~166 GiB);也可走 NFS 免复制(见 §9.1)

## 2. 硬件与网络要求

### 2.1 硬件
- **2 台 DGX Spark**(或 2 台 128 GB 统一内存的 GB10 系统)
- 启动服务器时每台需 **~110 GiB 空闲 GPU 内存**(不得有其他大型 GPU 任务)

### 2.2 ConnectX-7 直连链路(必做)
1. 用 **QSFP 线**直连两台 Spark 的 CX7 端口
2. 两端各配一个同私有子网的 IPv4,例如 `192.0.2.1/24` 和 `192.0.2.2/24`,`ping` 必须通
3. 链路需有 **RoCE v2 GID**(`start.sh` 会自动检查)
4. 注意:Spark 的一个 QSFP 端口经两条 PCIe Gen5 x4 连到 GB10,表现为 **两个网卡 + 两个 RoCE 设备**(`enp1s0f0np0` / `enP2p1s0f0np0`,`rocep1s0f0` / `roceP2p1s0f0`)。**两端的双生口都要配地址**(可同子网或各配子网),双轨道时 all-gather 快 ~1.8 倍

### 2.3 软件前置(两台都要)
- Docker + NVIDIA 容器运行时,当前用户在 `docker` 组
- `rsync`
- **从 head 到 worker 的 SSH 免密登录**(head 运行 `./start.sh` 和 API,worker 无需克隆仓库)

## 3. 部署步骤

### 步骤 1:配置 CX7 链路(两台各执行)

```bash
# 示例:给 CX7 的两个网口配同子网地址(按实际接口名调整)
sudo ip addr add 192.0.2.1/24 dev enp1s0f0np0
sudo ip addr add 192.0.2.3/24 dev enP2p1s0f0np0   # 第二条轨道
ping 192.0.2.2   # 必须通
```

### 步骤 2:配置 SSH 免密(在 head 上执行)

```bash
ssh-keygen -t ed25519                # 没有密钥时
ssh-copy-id user@<worker地址>
ssh -o BatchMode=yes user@<worker地址> true   # 验证免密成功,无输出即 OK
```

### 步骤 3:克隆仓库并配置(仅在 head 上)

```bash
git clone https://github.com/MiaAI-Lab/GLM-5.3-Flash-EXL3-2x-DGX-Sparks-TensorFold.git
cd GLM-5.3-Flash-EXL3-2x-DGX-Sparks-TensorFold
cp scripts/local.sh.example scripts/local.sh
```

编辑 `scripts/local.sh`,至少设置:

```bash
WORKER=user@192.0.2.2      # worker 的 ssh 目标
# FABRIC_PEER=192.0.2.2    # 若 WORKER 走的是其他网络地址,需额外指定其 CX7 地址
```

### 步骤 4:一条命令启动

```bash
./start.sh
```

### 首次运行自动完成的内容(`scripts/prepare.sh`,可安全重跑)

1. **预检**(两台):Docker、GPU、rsync、SSH 免密、RoCE 链路、磁盘空间
2. **head 上构建/拉取镜像** `tensorfold-glm53:v0.6.0`(默认按 digest 拉 GHCR 预编译镜像;改过 `patches/` 则本地构建)
3. **镜像同步到 worker**(拉取,或 `docker save | docker load` 流式传输,校验一致)
4. **下载模型**:checkpoint(~176 GB)+ DFlash2(~2.3 GB)到 head 的 `~/.cache/huggingface`(用 `tensorfold info` 校验),再 rsync 复制到 worker 并逐文件校验(支持断点续传)
5. **CUDA 内核编译**:每镜像一次,缓存在 `~/.cache/tensorfold-glm53/<image hash>`

然后 `start.sh`:先在 worker 上经 ssh 启动 rank 1,再在 head 启动 rank 0 和 API;显示加载进度(首次约需下载+编译,之后每次 **2-6 分钟**加载 ~80 GiB 权重);跑一次贯通两 rank 的冒烟测试,最后打印:

```
GLM-5.3-Flash-EXL3 is now LIVE! on port 8888
```

# 服务健康(busy 标志、流数、池内空闲 token)
curl -s http://<head地址>:8888/health

# 模型列表

## 5. 使用 API

任何 OpenAI 客户端均可:`base_url = "http://<head地址>:8888/v1"`,模型名 `GLM-5.3-Flash-EXL3`。

### 5.1 图像 / 视频输入

```bash
IMG=$(base64 -w0 photo.jpg)
curl -s http://<head地址>:8888/v1/chat/completions -H 'Content-Type: application/json' -d '{
  "model": "GLM-5.3-Flash-EXL3",
  "messages": [{"role": "user", "content": [
    {"type": "image_url", "image_url": {"url": "data:image/jpeg;base64,'"$IMG"'"}},
    {"type": "text", "text": "What is in this picture?"}]}],
  "max_tokens": 2000
}'
```

- 图片:JPEG/PNG/WebP,单请求最多 50 张(每张 10 MB,共 64 MB);视频:MP4/WebM/MOV/MKV,最多 4 段(每段 64 MB,共 96 MB),2 fps、每段最多 128 帧
- 视频用 `{"type": "video_url", "video_url": {"url": "data:video/mp4;base64,..."}}`
- 默认仅接受 data URL;`VISION_URLS=1` 可放开公网 `https://` URL;`VISION=0` 纯文本省 ~1.8 GiB

### 5.2 思考与采样

- 采样默认:temperature 1.0、top_p 0.95;每请求可覆盖 `temperature` / `top_p` / `top_k` / `min_p` / `seed`
- `reasoning_effort`: `"low"` / `"high"` / `"max"`(默认 max);`"none"` 或 `"chat_template_kwargs": {"enable_thinking": false}` 关闭思考
- 思考内容在 `reasoning_content`,答案在 `content`;`content` 为空说明思考耗尽了 `max_tokens`

### 5.3 其他端点

`/v1/completions`、`/v1/responses`、`/tokenize`、`/detokenize`、Prometheus `/metrics`;结构化输出(`response_format` / `guided_json` 等,xgrammar);上下文超限按 OpenAI 格式返回 400 `context_length_exceeded`。

## 6. 日常运维

```bash
./start.sh restart                    # 重启两 rank(改配置后)
./stop.sh                             # 停止并释放两台 GPU 内存
docker logs -f glm53-flash-tf         # rank 0 日志(head)
ssh <worker> docker logs -f glm53-flash-tf   # rank 1 日志(worker)
./start.sh restart --max-tokens 16384 # 追加参数,覆盖默认值
FOREGROUND=1 ./start.sh               # 前台运行,适配 systemd
```

**历史日志**:stop/重启前自动打包到 `~/.cache/tensorfold-glm53/logs/<日期>-<时间>-rank<N>.log.gz`(每台保留最新 10 份),用 `zcat`/`zless` 查看;报 crash 时附上两 rank 的日志。

## 7. 常用配置项

配置方式:环境变量单次生效 > `scripts/local.sh` > `.env` > 默认值。全部定义在 `scripts/config.sh`。

| 变量 | 默认 | 说明 |
|---|---|---|
| `WORKER` / `FABRIC_PEER` | 空 | worker 的 ssh 目标 / 其 CX7 地址(WORKER 不在链路子网时必设) |
| `PARALLEL` | `4` | 并发请求数 1-8(>1 需 DFlash2);8 并发比 4 并发总吞吐 +27-36%,但共享池更小 |
| `CONTEXT` | `1048576` | 每请求 prompt+回复窗口;`0` = 自动取最大可容纳值 |
| `KV` | `fp8` | KV 精度;`bf16` 精确但窗口缩短(196,608) |
| `DENSE` | `q4` | 稠密权重精度;**非英文短 prompt 建议 `fp8`**(q4 在法语短编码 prompt 上可能丢失停止符,issue #18),代价 ~10% 速度 |
| `DRAFTER` | `dflash2` | `mtp` 用 checkpoint 自带 MTP 头(避开非商用许可,仅单并发) |
| `ABLIT` | `0` | `1` 用 Ablit 权重(需 HF_TOKEN,默认关思考) |
| `WORKER_WEIGHTS` | `copy` | `nfs`:worker 经 NFS 只读挂 head 的 HF 缓存,免复制 |
| `THINKING` | `1` | 默认是否先思考 |
| `VISION` / `VISION_URLS` | `1` / `0` | 视觉开关 / 是否接受公网 URL |
| `SERVED_NAME` / `PORT` / `HOST` | `GLM-5.3-Flash-EXL3` / `8888` / `0.0.0.0` | 模型名与监听地址 |
| `MAX_TOKENS` | `32768` | 请求未指定 `max_tokens` 时的回复预算 |
| `KV_POOL_GIB` / `MEMORY_RESERVE_GIB` | `12.5` / `14.5` | 共享 KV 池上限 / 宿主预留(并发越高预留越大) |

改完配置后:`./start.sh restart`。

## 8. 进阶选项

### 8.1 Worker 权重走 NFS(省 166 GiB 复制)

head 上一次性导出(需 root):

```bash
sudo apt install nfs-kernel-server
echo "$HOME/.cache/huggingface <worker的CX7地址>(ro,no_subtree_check)" | sudo tee -a /etc/exports
sudo exportfs -ra
```

然后 `scripts/local.sh` 里设 `WORKER_WEIGHTS=nfs`,执行 `./start.sh restart`。加载速度与本地盘相当(两 rank 约 2.2 分钟起服务)。

### 8.2 三台 Spark(实验性)

`./start-tp3.sh`:三角环状 QSFP 布线(每对直连一条线、各成子网),`scripts/local.sh` 设 `WORKER` + `WORKER2`。4 并发 prose 146.2 tok/s(对比双机 108.8),默认 `PARALLEL=8`。`DRY_RUN=1 ./start-tp3.sh` 可预览。

### 8.3 更新

```bash
scripts/prepare.sh            # 只做初始化,不启服务(幂等,可重跑)
scripts/prepare.sh --rebuild  # 改了 patches/ 或 MODEL_ID/TF_VERSION/BASE_IMAGE 后重建镜像
PREPARE=1 ./start.sh restart  # 强制先 prepare 再重启;PREPARE=0 跳过检查
```

模型 revision 有 pin(`MODEL_REVISION` / `DFLASH2_REVISION`),上游更新不影响已部署版本。

## 9. 常见问题排查

`start.sh` 中途停下时的提示与处理:

| 报错 | 处理 |
|---|---|
| `only N GiB memory available` | 该机还有其他 GPU 任务:`docker ps` 停掉后重启 |
| `no RoCE device or RoCE v2 GID for the link` / `no route from this node to ...` | 到 worker 的路由没走 CX7 口:设 `FABRIC_PEER` 为 worker 的 CX7 地址,`ip -4 addr` 确认两端都配了地址 |
| `the worker's .../hub is not writable` | 之前容器把缓存目录变成 root 属主:到 worker 上修复目录属主 |
| 窗口装不下 | 自动以可容纳的最大窗口重启一次(两台都要有足够空闲内存才能开满 1M 窗口) |
| NCCL error 2(首连失败) | 自动降级 `SPLIT=0` 重试 |

其他:
- **内存耗尽倾向直接死机**(统一内存),不会报 OOM——务必保证启动前 ~110 GiB 空闲
- rank 卡死超过 300 s(`TF_GLM_MULTI_WATCHDOG_S`)自动打印全部线程栈;`TF_GLM_MULTI_WATCHDOG_EXIT=1` 让其退出以便 supervisor 拉起
- Prometheus `/metrics` 与 `/health`(`pool_tokens`、`pool_free_tokens`、各流状态)可用于监控

## 10. 性能参考(默认配置,sparkDash 实测)

| 并发 | Prose 总吞吐 | 单路 | TTFT |
|---|---|---|---|
| 1 | 60.4 tok/s | 60.4 | 170 ms |
| 4 | 108.8 tok/s | 27.9 | 340 ms |

- Prefill:~1,950-2,000 tok/s(8k-131k prompt);98 万 token 大海捞针 1,015 tok/s
- 提示复用:相同 64k prompt 二次发送 < 0.07 s(首次 34 s)
- 质量(GSM8K 98.8%、HumanEval 95.7%);投射 token 全部经模型自身采样校验,并发回复与串行逐 token 完全一致
