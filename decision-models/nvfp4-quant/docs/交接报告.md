### 2.3 安装版本的 API 事实（以实际安装源码为准，不照抄在线文档）

```python
nvfp4_quantize(a, a_global_sf, sfLayout=SfLayout.layout_128x4, do_shuffle=False,
               sf_vec_size=16, enable_pdl=None)
# 返回 (packed uint8 [M, K/2], scale uint8 [PR, PC])   ← 注意 scale 是 2D 且已 padding
# SfLayout = {layout_128x4: 0, layout_8x4: 1, layout_linear: 2}
```

与在线文档的差异（都在本仓库脚本里做了适配）：

1. 返回的 scale 是 **2D `[PR, PC]`**（`PR = ceil(M/128)*128`, `PC = ceil((K/16)/4)*4`），
   不是一维扁平缓冲；
2. `a_global_sf` 必须是 **float32、shape [1]**，由调用方按 `448*6/amax` 算好传进去；
3. `do_shuffle=False` 时 scale 已经是 128x4 swizzled，**下游不要再 shuffle**。

## 3. 量化执行

```
允许清单 723 条判定：A 96 / B 32 / C 72 = 200 量化，523 保留
量化耗时 289.8 s：读 8.9 GB BF16 → 写 3.95 GB NVFP4
输出 1 个分片 model-00001-of-00001.safetensors（1123 key）
```

逐 tensor 流程：读 BF16 → 搬到 GPU → `amax = max|W|`（fp32）→ `global_sf = 448*6/amax` →
`nvfp4_quantize(...)` → packed / swizzled scale / global scale 搬回 CPU → 攒够 4.5 GB 落一个分片。
`global_sf` 为 per-tensor（Max PTQ），block scale 为 per-16 元素，粒度与 NVFP4 规范一致。

## 5. 下游 W4A4 接入要点

1. **权重直接可用**：`weight_fp4` / `weight_scale` / `weight_global_scale` 就是
   FlashInfer `mm_fp4` 需要的 B 矩阵三件套（swizzled 128x4，`do_shuffle=False`），不要再变换。
2. **自己做 activation 量化**：`mm_fp4` 需要 A 侧的 fp4 packed + per-16 block scale +
   per-tensor global scale，按同样公式（`448*6/amax`）在线算。这块**不在本 checkpoint 内**。
3. **命名映射**：`<prefix>.weight` → `<prefix>.weight_fp4` / `.weight_scale` / `.weight_global_scale`；
   `nvfp4_manifest.json` 的 `tensors[].nvfp4` 字段有逐条对应关系。
4. **未量化权重按原逻辑加载**，它们与 BF16 原 checkpoint 逐位一致。
5. **不要在加载时再做 fake quant / 反量化回 BF16 再算**——那就退化成 W4A16 了，不在验收范围；
   但如果只是想先跑通 shape/精度冒烟，`scripts/nvfp4_ref.py::dequantize_swizzled` 可以拿来做参照。

加载骨架：

```python
import json, torch
from safetensors import safe_open

ck = "/home/sakana/models/decision-models/pplx-decider-flash-v1.3-NVFP4"
idx = json.load(open(f"{ck}/model.safetensors.index.json"))["weight_map"]
man = {t["name"]: t for t in json.load(open(f"{ck}/nvfp4_manifest.json"))["tensors"]}

def load_weight(name):
    m = man[name]
    if m["status"] == "bf16_preserved":
        with safe_open(f"{ck}/{idx[name]}", framework="pt", device="cpu") as f:
            return f.get_tensor(name)
    nv = m["nvfp4"]
    with safe_open(f"{ck}/{idx[nv['weight']]}", framework="pt", device="cpu") as f:
        return (f.get_tensor(nv["weight"]),        # uint8 [N, K/2]
                f.get_tensor(nv["scale"]),         # uint8 [PR*PC]，128x4 swizzled
                f.get_tensor(nv["global_scale"]))  # float32 [1]
```

## 8. 风险与后续建议

| 风险 | 说明 | 建议 |
|---|---|---|
| 9.5% 权重误差 | NVFP4 固有；是否可接受取决于 W4A4 的 activation 量化与误差补偿 | 下游先跑决策一致性，再决定是否对 `down_proj`/`o_proj` 做混合精度 |
| `in_proj_z` 纳入 C 组 | 它是 4096×2560 的输出门，不是"小型 gate" | 若下游更保守，`./run.sh quantize --no-deltanet-z` 可退回 BF16 |
| swizzle / 位序实现 | 下游若自己写加载，最容易在这两处出错 | 用 `verify_nvfp4_ckpt.py` 的 rel_l2 / cosine 作为一致性门槛 |
| 单分片 3.95 GB | 加载器需支持单文件 + 索引 | 若下游按 `model-0000X-of-0000Y` 解析，注意 `Y=1` |
