# 决策模型部署（手把手）

> 五个模型：Bison 31B、Elephant 9B、Decider v1.3、Decider Flash v1.3、GLiDE-0.4B
> 目标机：`spark-d705`（DGX Spark，GB10，132 GB 统一显存），服务端 `192.168.101.2`
> 方案细节（运行时差异、性能数据、排障）见 [`部署流程.md`](./部署流程.md)

---

## 0. 你需要准备的东西

| 项目 | 要求 |
|---|---|
| 一台 DGX Spark | 装好驱动（`nvidia-smi` 正常）、Docker、CUDA 13（`/usr/local/cuda-13.0`）、Python 3.12 |
| 磁盘 | 模型 ~149 GB + wheelhouse ~1 GB + 运行环境 ~2 GB |
| 内存 | 同时常驻 3 个模型约 50 GB；bison(63 G) + decider(52 G) 不能与其它全部共存 |
| 网络 | 目标机可离线；下载机需要能访问 `hf-mirror.com`、`pypi.org`、`download.pytorch.org`、`archive.ubuntu.com` |
| new-api | 已有的 OpenAI 兼容网关（本例 `127.0.0.1:3000`），用于统一入口和计费 |

两台 Spark 的角色（本仓库的惯例）：

- **spark-adeb** `192.168.101.1`：下载 / 构建 / 管理机
- **spark-d705** `192.168.101.2`：推理机（本方案部署在这里）

## 2. 准备离线 wheelhouse（aarch64）

目标机没有外网，依赖必须在管理机下好再拷过去。

```bash
python3 -m pip download --only-binary=:all: \
  --platform manylinux_2_28_aarch64 --platform manylinux2014_aarch64 \
  --python-version 312 --implementation cp --abi cp312 --abi abi3 --abi none \
  -d wheelhouse \
  transformers==5.17.0 tokenizers==0.23.2 safetensors==0.8.0 pillow==12.3.0 \
  numpy jinja2 "huggingface_hub>=1.5" fastapi==0.142.2 "uvicorn[standard]" \
  pydantic filelock sympy networkx fsspec typing-extensions setuptools wheel \
  psutil pyyaml regex requests tqdm packaging

# torch 必须从 pytorch 官方 cu130 源取（PyPI 的 aarch64 torch 依赖不存在的 nvidia-cudnn-cu13）
python3 -m pip download --no-deps --index-url https://download.pytorch.org/whl/cu130 \
  --platform manylinux_2_28_aarch64 --python-version 312 --implementation cp --abi cp312 \
  -d wheelhouse "torch==2.14.0+cu130" "torchvision==0.29.0+cu130"

python3 -m pip download --no-deps -d wheelhouse accelerate
```

> `--abi abi3` 不能少，否则 `tokenizers` 找不到 wheel。

### 4.1 补 CUDA 库（关键）

aarch64 的 PyPI 没有 `nvidia-cudnn-cu13`，torch 导入会报 `libcudnn.so.9: cannot open shared object file`。
从本机已有的 GPU 镜像里抽：

```bash
CID=$(docker create image-gen-inference:0.6.0-resident)
docker cp "$CID:/usr/lib/aarch64-linux-gnu/." /tmp/cudalibs/
docker cp "$CID:/opt/venv/lib/python3.14/site-packages/nvidia" /tmp/nvpkgs/
docker rm "$CID"
rsync -a /tmp/nvpkgs/nvidia .venv/lib/python3.12/site-packages/
rsync -a /tmp/cudalibs/     cudalibs/
# 镜像里的 NCCL 是 2.27.7，torch 2.14 需要 2.30.7
cp cudalibs/libnccl.so.2.30.7 .venv/lib/python3.12/site-packages/nvidia/nccl/lib/libnccl.so.2
```

验证：

```bash
.venv/bin/python -c "import torch;print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
# 2.14.0+cu130 True NVIDIA GB10
```

### 4.2 装 qev（OneJev + Base Labs 补丁）

```bash
git clone https://github.com/OmniJev/OneJev.git serving/onejev
cd serving/onejev && git checkout 81ce62f1597c91e46767d4d02d6ac2e18534fe94
git apply ../../serving/serve.patch
/home/sakana/models/decision-models/.venv/bin/pip install --no-index --no-build-isolation --no-deps -e .
```

### 4.3 装 flash-linear-attention（长上下文提速 2x，必装）

triton 需要 Python 头文件，而系统没装 `python3.12-dev`：

```bash
cd /tmp && mkdir pydev && cd pydev
apt-get download python3.12-dev libpython3.12-dev
for f in *.deb; do dpkg-deb -x "$f" /tmp/pydev; done
```

把 `sitecustomize.py`（见 `docker/sitecustomize.py`）拷到 `.venv/lib/python3.12/site-packages/`，
然后：

```bash
export C_INCLUDE_PATH=/tmp/pydev/usr/include
export LIBRARY_PATH=/usr/local/cuda/lib64:/lib/aarch64-linux-gnu
.venv/bin/pip install --no-index --no-deps \
  triton fla-core flash-linear-attention einops        # 包从管理机的 wheelhouse 同步
.venv/bin/python -c "import fla; print('fla', fla.__version__)"
```

> 不装也能跑，但线性注意力会走参考 PyTorch 实现，长上下文慢一倍。

### 4.4 装 cuDNN 9.24（启用 CUDA graphs 的前提）

`PPLX_FAST=1` 会检查 cuDNN 版本，venv 里如果是从镜像拷来的 9.13 会直接报错。NVIDIA 的 sbsa 归档里有对应版本：

```bash
curl -sSL -o /tmp/cudnn.txz \
  https://developer.download.nvidia.com/compute/cudnn/redist/cudnn/linux-sbsa/cudnn-linux-sbsa-9.24.0.43_cuda13-archive.tar.xz
mkdir -p /tmp/cudnn924 && tar -xJf /tmp/cudnn.txz --strip-components=1 -C /tmp/cudnn924
CU=/home/sakana/models/decision-models/.venv/lib/python3.12/site-packages/nvidia/cudnn
cp -a /tmp/cudnn924/lib/libcudnn*.so* $CU/lib/
python -c "import torch;print(torch.backends.cudnn.version())"   # 期望 92400
```

> 归档约 1 GB，下载可能断，用 `curl -C -` 续传并 `tar -tJf` 校验完整性。

## 5. 启动服务

### 5.1 容器化（推荐，当前线上方式）

```bash
cd /home/sakana/models/decision-models/serving
docker compose up -d          # gw-elephant:8012 / gw-flash:8014 / gw-glide:8015
docker compose ps
```

compose 里已经带好：`--gpus all`、权重只读挂载、`PPLX_MODE=isolated`、`PPLX_FAST=1`、
CUDA graph 预热桶，以及 Triton/CUDA 的 JIT 缓存卷（容器重建后不用重新编译）。

> 首个**新序列长度**的请求仍会多花 7–15 s（Triton 现场编译 + CUDA graph 捕获），
> 之后稳定在上面的数值。换长度就重新付一次，属于 Triton 的 shape 特化行为。

### 5.2 venv 方式（调试用，二选一）

```bash

```

## 8. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `libcudnn.so.9: cannot open shared object file` | 没补 CUDA 库 | 见 4.1 |
| `undefined symbol: ncclCommResume` | NCCL 版本旧 | 换成 2.30.7 |
| 启动卡在 `Module.to` 几分钟 | torch 逐张量搬运慢 | 已用 `safe_open(device="cuda")` 绕过，确认补丁生效 |
| `chunk_gated_delta_rule ... falling back` | 没装 fla | 见 4.3 |
| `cuDNN version incompatibility (9.24 vs 9.13)` | 开了 `PPLX_FAST=1` | 保持 `PPLX_FAST=0` |
| new-api「测试渠道」超时 | new-api 测试逻辑问题，不是链路问题 | 直接用 `/v1/chat/completions` 验证 |

更多排障见 [`部署流程.md`](./部署流程.md) 第 8 节。
